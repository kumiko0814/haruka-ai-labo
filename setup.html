AI活用ラボ 設置ガイド

このガイド1枚で、別の会社様・別の講師の方でも、同じ仕組みをゼロから立ち上げていただけます。全体の所要時間の目安は約1時間です（このうちSupabaseの作成にかかる時間は10分ほどです）。

Claude Code をお使いなら、このフォルダを開いて「設置ガイド（setup.html）に沿って進めて」と話しかけるだけで、STEP1〜6 を Claude が案内・代行します。設定ファイルの書き換え・人格の差し替え・公開まで、コードを触る必要はありません。運用の仕方は 引き継ぎ書 をご覧ください。

全体の流れ STEP1 複製 STEP2 設定 STEP3 差し替え STEP4 本番化 STEP5 公開 STEP6 自動下書き チェックリスト

STEP 0　全体の流れ

複製から公開まで、次の6つの作業だけで完了します。順番に進めてください。

  1. リポジトリを複製する（GitHub上でコードを丸ごとコピーします）
  2. labo_config.js を書き換える（サービス名・講師名・価格・日程・リンクなど）
  3. キャラクター画像とAIの人格を差し替える
  4. Supabase（無料のデータ保存先）を作って本番化する
  5. GitHub Pagesで公開する
  6. 自動下書きルーティンを登録する（Meroneが運用代行する場合は不要です）

STEP 1　リポジトリを複製する

① GitHubのアカウントをお持ちでない場合は、github.com で無料登録してください（メールアドレスで1〜2分ほどです）。

② 元になっているリポジトリのページを開き、画面右上にある「Fork」というボタンを押します。これで、まったく同じ中身のコード一式が、ご自身のGitHubアカウントの中に複製されます。

③ 「Fork」の代わりに、リポジトリの「Code」ボタン→「Download ZIP」で中身をダウンロードし、ご自身で新しく作ったリポジトリにアップロードする方法でも構いません。

この後の作業は、すべて複製後のご自身のリポジトリの中で行います。元のリポジトリを直接書き換えることはありません。

STEP 2　labo_config.js を書き換える

GitHubのブラウザ上での書き換え方

① 複製したリポジトリで labo_config.js を開きます。
② 画面右上の鉛筆マーク（Edit this file）を押します。
③ 「 」の中の文字だけを書き換えます（前後の引用符やカンマは消さないでください）。
④ 画面下までスクロールし、「Commit changes...」ボタンを押して保存します。

よくある失敗：文字列を囲んでいる " を消してしまう／項目の最後にあるカンマ（,）を消してしまう／全角の「”」や「，」を使ってしまう（半角の " と , を使ってください）。保存後にLPが真っ白になった場合は、まずこの3点を確認してください。

STEP 3　キャラクター画像とAIの人格を差し替える

① キャラクター画像（5点）

assets フォルダの中にある次の5つの画像を、同じファイル名・PNG（背景透過）のまま、ご自身のキャラクター画像に置き換えるだけで反映されます。コードの編集は不要です。推奨サイズは縦500〜600ピクセル程度の全身立ち姿です。

ファイル名使われている場所
hk-suit.pngLPのヒーロー（ページ最上部）
hk-desk.pngAIチャットのアイコン
hk-cake.pngLPの「ナビゲーター」紹介
hk-casual.pngLPのマイページ説明
hk-laptop.png引き継ぎ書（handover.html）のヒーロー

② AIの人格

ai.html の中にある var RULES=[ 以下が、AIチャットの自動応答の中身です。ここをご自身の講師の方の文体・持論に書き換えます。

まず、講師の方の「人格設計資料」をご用意ください。プロフィール、価値観、口調のくせ、よく使うフレーズ、模範的な回答例3本、言ってほしくないこと（NG事項）をまとめたもので構いません。それができたら、Claude（claude.ai）にai.htmlの中身とこの資料を貼り付けて、下のプロンプトをそのまま送ってください。

添付（貼り付け）した ai.html のRULESには、AIチャットの自動応答が入っています。
別紙の「講師の人格設計資料」をもとに、RULES内のreplies（返信文）を、この講師の文体・言い回し・持論に全面的に書き直してください。

条件：
・re:（反応する言葉のパターン）と replies:（返信の配列）という構造は変えないでください
・価格・日程・締切などlabo_configから読み込んでいる部分（CF("…")の記述）はそのまま残してください
・1メッセージにつき絵文字は1〜2個程度に抑えてください
・返信は2〜3通程度の短い文章の組み合わせにしてください

書き直したRULES全体を、コピーしてそのまま貼り替えられる形で出力してください。

③ 講師のプロフィール文章

lp.html の中の「ナビゲーター」というセクション（<div class="eyebrow">INSTRUCTOR</div> の少し下）にある紹介文の段落を、ご自身の講師の方の経歴・実績・想いに書き換えてください。お名前・呼び名・肩書きはlabo_config.jsの内容が自動で入りますので、ここでは経歴部分の文章のみ書き換えます。

④ 色を変えたい場合（任意）

各HTMLファイルの先頭付近にある :root{ --navy... } という部分がブランドカラーの設定です。変更したい場合は、この部分をClaudeに「このサイトのメインカラーを〇〇色に変えて」と頼むと簡単です。

STEP 4　Supabaseを作って本番化する

Supabaseは、AIカルテのやり取りを保存しておくための、無料で使えるデータの保管庫です。作業は「SQLを貼って実行」を含めて1回だけです。

Merone が運用を代行する場合（はるかさんはこちら）：4-1・4-2・4-3 までを進め、できた Project URL と anon public キーの2つを Merone に送ってください。4-4 と 4-5 は Merone 側で行います。

4-1　Supabase（無料）のアカウントを作る

① supabase.com でアカウント作成（GitHubかメールで1分ほどです）
② 「New project」でプロジェクトを1つ作ります（名前は自由・リージョンはTokyo・無料プランでOKです）
③ できたら左メニューの「SQL Editor」→「New query」を開きます

4-2　下のSQLをコピーして貼り付け、「Run」を押す

create table if not exists ailab_notes (
  id bigserial primary key,
  member_id text not null,
  member_name text,
  mood text,
  worry text,
  want text,
  created_at timestamptz default now()
);
create table if not exists ailab_advice (
  id bigserial primary key,
  target_id text not null,
  author_name text default 'はるか',
  message text,
  created_at timestamptz default now()
);
alter table ailab_notes enable row level security;
alter table ailab_advice enable row level security;
drop policy if exists ailab_notes_all on ailab_notes;
create policy ailab_notes_all on ailab_notes
  for all to anon using (true) with check (true);
drop policy if exists ailab_advice_all on ailab_advice;
create policy ailab_advice_all on ailab_advice
  for all to anon using (true) with check (true);

4-3　接続テスト

Runが終わったら、このボタンを押してください。

4-4　接続情報をサイトに書き込む

Supabaseの左メニュー「Settings」→「API」を開き、Project URL と anon（publishable）キー をコピーします。
このサイトのファイル supabase_config.js を開いて、URLとキーを貼り付け、enabled を true にして保存してください。これで全ページが本番モードになります（それまでは安全なデモモードです）。

4-5　データ保護（削除ブロック・1回だけ／おすすめ）

このSQLを実行すると、サイトで使っている公開キーからはデータを消すことが不可能になります（書く・読む・返信はこれまで通りできます）。消せるのはSupabaseの管理画面を開ける方だけになります。

drop policy if exists ailab_notes_all on ailab_notes;
drop policy if exists ailab_advice_all on ailab_advice;
drop policy if exists ailab_notes_sel on ailab_notes;
drop policy if exists ailab_notes_ins on ailab_notes;
drop policy if exists ailab_notes_upd on ailab_notes;
drop policy if exists ailab_advice_sel on ailab_advice;
drop policy if exists ailab_advice_ins on ailab_advice;
create policy ailab_notes_sel on ailab_notes
  for select to anon using (true);
create policy ailab_notes_ins on ailab_notes
  for insert to anon with check (true);
create policy ailab_notes_upd on ailab_notes
  for update to anon using (true) with check (true);
create policy ailab_advice_sel on ailab_advice
  for select to anon using (true);
create policy ailab_advice_ins on ailab_advice
  for insert to anon with check (true);
無料プランは、1週間ほどアクセスがないと自動的に一時停止します。週に1回は管理者ボード（kanri.html）を開くようにしてください。もし停止してしまった場合は、Supabaseのダッシュボードを開き、「Restore」を押すと再開できます。

STEP 5　GitHub Pagesで公開する

① 複製したリポジトリの「Settings」タブを開きます。
② 左メニューの「Pages」を開きます。
③ 「Branch」を main（またはmaster）／ root に設定して「Save」を押します。
④ 数分待つと、https://ご自身のユーザー名.github.io/リポジトリ名/ というURLで公開されます。

独自ドメインをお持ちの場合は、同じ「Pages」の設定画面からご自身のドメインを追加することもできます（任意です）。

STEP 6　自動下書きルーティンを登録する

受講生から届くカルテに、講師本人の文体で返信の下書きを自動で入れる仕組みです。登録すると、運営者は管理者ボードで下書きを読み、「承認して送信」を押すだけで運用できるようになります。手順の全文は scripts/ailabo-draft/ROUTINE.md にあります。

6-1　プロンプトに人格設計資料を貼る

scripts/ailabo-draft/ROUTINE.md を開き、講師の人格設計資料（persona/persona_〇〇.md）の本文をコピーして、文中の {{PERSONA}} の位置に貼り付けます。あわせて {{LABO_NAME}} をサービス名に、{{NOTIFY}} を報告先（不要なら空欄のまま）に置き換えます。

6-2　Claude Code の /schedule で登録する

Claude Codeで「/schedule」と話しかけ、次の内容を伝えます。

項目内容
名前カルテ自動下書き（〇〇ラボ）
間隔毎日 7:40〜21:40 の2時間おき（JST・1日8回）
ソースこのリポジトリのGitHub URL
プロンプト6-1で作った本文

6-3　動作の確認

登録後、しばらく待ってから管理者ボードのカルテ受信ボックスを開きます。返信欄に「AI下書き（編集できます）」というバッジが出ていれば、正しく動作中です。

Meroneが運用を代行する場合、この登録はMerone側のアカウントで行います。運営者ご自身の作業はありません。ご自身で登録したい場合だけ、この手順をお使いください。

管理者ボードからURLを発行して、参加者に送るだけで運用開始です。
